deliver

A local CLI that runs a versioned acceptance spec and reports which checks passed. Built for agents and CI that need deterministic proof that expected deliverables exist and that quality gates still pass — with no network, no daemon, and no source code leaving the machine.

Quick start

deliver init                    # scaffold deliver.toml
deliver validate deliver.toml   # parse check, no runs
deliver --spec deliver.toml --allow-commands --strict

A spec is TOML or JSON. A run prints a report — deliver report: PASS or FAIL — one row per check. With --strict, a failing run exits 1; usage and parse errors exit 2. Without --strict the exit code is always 0 and the report carries the outcome.

Checks

File checks [[file]]

Paths are relative to --base and may not escape it, including through symlinks.

Command checks [[command]]

Run a program from a working directory under --base. cmd takes an argument array (preferred) or a whitespace-split string; validate with expect_exit, stdout_contains, stderr_contains; bound it with timeout_secs (default 300; on Unix the whole process group is killed). Output is capped at 1 MiB per stream. Requires --allow-commands.

Directory checks [[directory]]

required, min_files / max_files (regular files directly inside, non-recursive), forbid_empty.

Git checks [git]

Run last, sequentially, in --base: no_uncommitted_changes, no_untracked_files, require_branch_regex, require_commit_message_regex.

Conditional checks (when)

Any file, command, directory, or plugin check may declare skip conditions. When a condition does not hold, the check is skipped, not failed: it reports pass = true with a skipped flag, never fails the run, and is excluded from weighted completion.

[[file]]
path = "Cargo.lock"
when = { file_exists = "Cargo.toml", os = "linux" }

file_exists is a base-relative path; os is linux, macos, or windows (case-insensitive). Conditions combine with AND. This is how a shared base policy carries Cargo-specific checks that only activate in Rust repositories.

Weights

Any check may declare weight (default 1.0). Weights never change pass/fail; when at least one check has a weight, the summary gains a weighted completion percentage:

14 checks: 9 passed, 5 failed in 120 ms · 64% complete by weight

Spec composition (extends)

extends = "../policies/rust-lib.toml"

Resolved relative to the declaring spec. Checks accumulate (parent first); git flags combine with OR, so a child can only add requirements. Circular chains are rejected. extends is only honored when loading from a file (--spec / deliver validate).

Plugin checks ([[plugin]], protocol v1)

The extension point for organization-specific checks. The runner spawns your program, writes one JSON request line to stdin, closes it, and expects one JSON response on stdout with exit 0:

request:  {"protocol": 1, "name": "org gate", "base": "/abs/path"}
response: {"pass": true, "message": "all good"}

pass (boolean) is required; message is optional; extra fields are ignored. A nonzero exit, unparseable stdout, a missing pass, or output over 1 MiB per stream fails the check with the plugin's stderr quoted (truncated to 500 chars). Plugins support cwd, timeout_secs (process-group kill on Unix), weight, and when, run in the parallel pool, and accumulate across extends. A runnable example lives in examples/plugin/.

SBOM gate ([sbom])

[sbom]
required = true
formats = ["spdx", "cyclonedx"]   # empty = any supported

Searches *.spdx, *.spdx.json, *.cdx.json, and bom.json under --base for SPDX (JSON or tag-value) or CycloneDX documents with their core fields present. Detection is deliberately shallow: the gate proves a well-formed SBOM exists, not that its contents are accurate.

Output formats

text (default)
Terminal report with suggestions on failure.
json
Stable single-object report; check objects carry name, pass, kind, message, optional weight, optional skipped.
sarif
SARIF 2.1.0; failed checks only, for GitHub code scanning.
junit
JUnit XML; every check is a testcase, failures carry <failure>, skips carry <skipped/>.
ndjson
One {"type":"check",…} line the moment each check finishes, then a {"type":"summary",…} line — for watchers that react to partial progress. Spec order with --jobs 1, completion order otherwise.
github
GitHub Actions workflow commands: failing checks become ::error annotations, plus one ::notice summary.

Subcommands: init, validate, completions, schema (JSON Schema draft-07 for the spec format, for editor support), keygen, and attest verify.

Performance

--jobs N
Parallel check execution; 0 uses all CPUs. Report order is always spec order.
--cache-dir DIR
Content-hash result cache: file checks replay for identical content, keyed by deliver version + full check definition, always marked (cached). Never a gate.
--incremental
Git-diff-aware: files unchanged since HEAD replay their HEAD-pinned results without being re-read. Requires a git repository with a commit; implies the default cache dir ($XDG_CACHE_HOME/deliver).
--fail-fast
Stop after the first failure; remaining checks are reported as skipped.

Attestations

deliver keygen --out keys        # keys.key (0600) + keys.pub
deliver --spec deliver.toml --allow-commands \
    --attest bundle.json --attest-key keys.key
deliver attest verify bundle.json --pub keys.pub

--attest writes a bundle only after a passing run: spec hash, report hash and tallies, git commit, UTC timestamp, and an Ed25519 signature over the canonical payload. Verification always checks payload integrity; --pub additionally authenticates the signer. Verification proves the bundle is intact and who signed it — it does not re-run the checks.

Trust model

--allow-commands (required for command and plugin checks) is an execution consent flag, not a sandbox: commands and plugins inherit the runner's privileges, environment, and network. Review the spec and its full extends chain before passing it; run untrusted repositories only in isolated, low-privilege CI jobs. Spec parsing is fail-closed (unknown fields are errors), check paths cannot escape --base, failed command checks never echo expected output values, and secret findings never echo matched content.

Library API

deliver is also a library crate. Load a spec, run it, read the report:

use deliver::{Spec, ValidateOptions};

let spec = Spec::load_file(std::path::Path::new("deliver.toml"))?;
let report = spec.validate_with_options(base, jobs, &ValidateOptions::default())?;
assert!(report.pass);

From 1.0 the crate follows Semantic Versioning. Everything reachable from the crate root is public API, including the serialized shapes (JSON reports, attestation bundles, plugin protocol v1). Spec fields are fail-closed, so adding one is a minor change; removing or reinterpreting one requires a major. MSRV is Rust 1.74, documented in Cargo.toml, and the crate denies missing documentation so every public item is specified.
